# Changelog

This changelog documents test-only work on the vendored `semver` 1.0.28 code
(dtolnay/semver @ 280ebcb). **No product semantics were changed**; the only
shipped diff is the new integration test file
[`tests/test_sso_boundary.rs`](tests/test_sso_boundary.rs), plus this record.

## Unreleased — Identifier 8/9 boundary and parse-display-eval invariants

### What was added

A single, independently runnable integration test target
(`cargo test --test test_sso_boundary`) with 13 tests, each locatable on its
own (`cargo test --test test_sso_boundary -- <name>`):

- `sso_boundary_length_matrix` — identifiers at lengths 0, 1, 2, 7, 8, 9
  (and 126/127/128/129/200 off-miri, covering the varint 1/2-byte seam)
  through both `Prerelease::new` and `BuildMetadata::new`, checking `len`,
  `as_str`, `is_empty` on both sides of every boundary.
- `sso_boundary_clone_is_independent` — Clone/Drop across the seam: dropping
  a clone before the original, and repeated allocator churn 8 ↔ 9.
- `sso_boundary_numeric_ord_crosses_seam` — generated numeric ordering at
  every seam-adjacent length, numeric-vs-alphanumeric, prefix, dot-separated
  components, and the empty(pre)/release ordering.
- `sso_boundary_build_metadata_leading_zero_ord` — build-metadata-specific
  `0 < 00 < 1 < 01 < 001 < 2` order with zero padding that straddles 8/9.
- `sso_boundary_hash_matches_eq` — Hash/Eq driven by contents, never by the
  inline/heap representation, for identifiers and for `Version`.
- `generated_identifier_orders_are_total` — property-style finite-alphabet
  generator (numeric/alphanumeric/hyphen/dot components at seam lengths);
  asserts totality, antisymmetry, and transitivity of `Ord` over the full
  pairwise matrix, plus representation-independent sort permutation, for
  both `Prerelease` and `BuildMetadata` (the latter with leading zeros).
- `parse_display_parse_roundtrip_matrix` — Cartesian pre × build length
  matrix (including empty) for `parse → Display → parse`, plus field
  identity with the symmetric `Prerelease::new`/`BuildMetadata::new` entry
  points and a `u64::MAX` extreme-value roundtrip.
- `build_metadata_invisible_to_precedence_visible_to_order` — the central
  SemVer/SSO invariant (see "Most dangerous counterexample" below).
- `leading_zero_asymmetry_at_pre_build_seam` — length-8 and length-9 leading
  zeros rejected in prerelease (via `Version::parse`, `Prerelease::new`,
  `VersionReq::parse`, `Comparator::parse`) but accepted/preserved in build
  metadata; lone `"0"` stays legal.
- `overflow_and_recovery_keep_diagnostic_context` — u64 overflow at
  major/minor/patch with position-specific messages; leading-zero priority
  over overflow; failure recovery (a rejected parse names `pre-release` or
  `build metadata` and never poisons the next parse) on both seam sides,
  including illegal-character rejection at lengths 8 and 9.
- `prerelease_admission_truth_table_across_seam` — the prerelease-admission
  rule (`*`/wildcard and pre-less reqs never admit prereleases; an explicit
  prerelease comparator at the same major.minor.patch admits them) exercised
  with 8- and 9-byte prereleases across `*`, `=`, `^`, and multi-comparator
  reqs, including numeric ordering at the seam (`99999999 < 999999999 <
  1000000000`).
- `build_metadata_ignored_by_matching_matrix` — build metadata on req and
  candidate sides never changes a match across a req × pre × build matrix;
  build on a comparator parses but is discarded; `*+…` is rejected.
- `req_parse_display_preserves_matching_across_seam` —
  `parse → Display → parse` preserves comparator structure and the full
  matching truth table for seam-crossing prereleases.

### Implementation choices

- **Tests only, no parallel implementation.** All assertions go through the
  public API; the private inline/heap distinction is treated as
  unobservable. Long (varint-seam) cases are gated on `cfg!(miri)` with the
  same cutoff convention already used in `tests/test_identifier.rs`.
- **Determinism.** No RNG, sleeps, network, or clock use; all inputs are
  generated by small pure functions over explicit boundary lengths.
- **Diagnostics.** Failure cases assert the full public error message,
  including the identifier position ("pre-release identifier" vs "build
  metadata") and numeric-field position (major/minor/patch).
- **Three verification directions** as required: both sides of each
  boundary (length matrix), symmetric entry points (Version/Prerelease/
  BuildMetadata/Comparator/VersionReq parsers), and failure recovery.

### Coverage gaps in the original suite

- `test_identifier` exercised one growing numeric string and a handful of
  Eq cases: never length 0 as a non-empty-growth case through both wrapper
  types, never a cross-representation *numeric* ordering pair (`8`/`9`
  bytes, `127`/`128` varint bytes), and never Hash semantics across
  representations.
- Version tests asserted build metadata affects total order
  (`1.2.3+23 < 1.2.3+42`) but never asserted the *converse precedence*
  invariance (`cmp_precedence` equal while `Ord` differs), let alone for a
  pair where numeric Identifier order disagrees with ASCII order.
- VersionReq tests covered prerelease admission only with short (< 8 byte)
  prereleases and never as a req-side × candidate-side build-metadata
  matrix; comparator build metadata being discarded from eval had no
  explicit assertion.
- No test combined parse-display-parse with pre/build lengths that take
  different storage representations.

### Mutation evidence (new tests genuinely fail)

Three boundary-logic mutations were applied to product code temporarily,
each failed a specific new test, and were then reverted:

1. Leading-zero predicate changed from `segment_len > 1` to a length
   special-case (`== 8`) in `identifier()` →
   `leading_zero_asymmetry_at_pre_build_seam` fails (9-byte `"000000000"`
   wrongly accepted as prerelease, `"00"` wrongly rejected).
2. Checked numeric accumulation changed to `wrapping_mul`/`wrapping_add`
   in `numeric_identifier()` → `overflow_and_recovery_keep_diagnostic_context`
   fails (20-digit overflow parses as 0 instead of an `Overflow` error).
3. Dropped `!cmp.pre.is_empty()` from `pre_is_compatible()` →
   `prerelease_admission_truth_table_across_seam` fails (a prerelease-less
   range req starts admitting prereleases at other mmp).

Additionally, moving the inline/heap seam itself (`1..=8`/`9..` to
`1..=7`/`8..` in `Identifier::new_unchecked`) compiled and **all 13 tests
still passed**, as did the existing suite. This is deliberate: the SSO
threshold is an internal representation choice and must be unobservable;
the contract that is pinned is content-level semantics, not the repr.

### Most dangerous counterexample and its regression test

The sharpest SemVer/SSO interaction is:

```text
1.0.0+99999999   (build = 99,999,999,  8 bytes → inline repr)
1.0.0+999999999  (build = 999,999,999, 9 bytes → heap repr)
```

- By raw ASCII/byte order the longer string sorts first (its first
  8 bytes equal `99999999`, then it continues); the two reprs even live in
  different storage (inline zero-padded bytes vs varint-headed heap).
- The correct **Identifier** order is numeric: `99999999 < 999999999`.
- The correct **SemVer precedence** ignores build metadata entirely:
  `cmp_precedence` is `Equal` both ways, while `Version`'s total `Ord`
  (and `Hash`) distinguishes them in the numeric direction. A mutation that
  compares build identifiers by repr bytes, or that lets build metadata
  leak into precedence/`VersionReq` matching, is wrong on one of these
  axes.

Regression coverage: `build_metadata_invisible_to_precedence_visible_to_order`
(explicit `Equal` precedence, numeric `<` build order, total `Ord`,
non-equal `Hash`, stable sort behavior), reinforced at the varint seam and
by `build_metadata_ignored_by_matching_matrix` for `VersionReq::matches`.

### Adjacent-semantics regression protection

- Build-metadata compare still owns its leading-zero-tolerant numeric
  order; prerelease compare still forbids leading zeros — asserted from
  every parser entry point.
- `u64::MAX` versions roundtrip; one digit more is an `Overflow` error at
  the correct position; leading zero beats overflow.
- `VersionReq` Display roundtrip is equality- and matching-preserving;
  build metadata on comparators remains parsed-and-discarded, and `*`
  remains a syntactically standalone comparator.
